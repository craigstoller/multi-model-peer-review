## 2026-10-04.2

A behavior change to the secret-file check in § *Secret files*, R26. A regular file whose name has a dotenv shape (`.env`, `.env.*`, `*.env`) and none of the check's other shapes is now read once, through `tr`, by an awk program the block carries, which reports counts only, never a line, a name or a value. When every line is blank, a comment, or an assignment whose whole value is empty or one 1Password secret reference, and at least one value is a reference, the file prints as `REFERENCE-ONLY (stays): <path> (<n> references)` in place of its path and is not treated as a secret, so a tree whose environment files hold only references keeps its file-reading engines without a move. The test checks each reference's shape, not that it resolves, so a key pasted where a name belongs passes as one. Anything else keeps the path listed: text after a reference, a value that runs onto another line, a byte-order mark, a NUL byte in a line the test judges, a commented-out assignment, however many `#`s precede it, whose value is neither empty nor a reference, a file with no reference. Other comment text is not judged, so a value written into a comment in any other form passes. The bytes judged are the bytes read: `tr` turns each NUL into another byte on the way in, since BSD awk ends a line at a NUL, and a file rewritten as the test reads it is judged on what was read. A link is listed whatever it points to, a template the check does not list stays unlisted, and a name that also has another secret shape, such as `credentials.env`, is not tested. A test that cannot run keeps the path listed and names it on stderr as `REFERENCE TEST COULD NOT RUN (listed): <path>`: `awk` or `tr` missing, or the file unreadable, gone or turned into a link. `DONE` and `INCOMPLETE` still report the walk. The panel line and the report name the reference-only files left in the tree, the report saying that an engine reading one sends its vault, item and variable names to its vendor, and a trace that shows one was read is reported once the check has been run on it again. `.secretguard-allow.psd1`, the secret guard's waiver file, joins the files whose name shows they are about the topic: it holds waived findings' paths and match hashes and has no field for their values. The Codex host's `check-secret-files.sh` carries the same `find` command and awk program and changed in the same commit.
